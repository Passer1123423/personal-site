本目录记录当前项目事实、运行维护说明、数据结构、API 和视觉约束。临时审计、一次性 follow-up 和已失效规划不放主目录；历史部署记录放在 `docs-archive/`。

1. `project-current-state.md`

4. `operations-and-deployment.md`
   - 本地运行、生产部署、环境变量、uploads、SQLite、备份和当前验证状态。

6. `style-guide.md`

## 当前事实源

- 前端：Vite + React + TypeScript + Tailwind CSS v4。
- 后端：FastAPI + SQLModel + SQLite。
- 认证：JWT Bearer token，token 存在前端 localStorage。
- 用户系统：注册、登录、个人主页、资料编辑、头像上传/裁剪/切换/删除。
- 漫画系统：Series、Part、Chapter、Page；作者归属在 Part 层。
- 小说系统：Novel、Chapter、Markdown 阅读、作者编辑器、正文 buffer、章节图片。
- 互动系统：通用评论、回复树、评论图片、用户页/小说/小说章节/漫画 Part/漫画章节挂载点。
- 收藏通知：小说/漫画 Part 收藏、OutboxEvent、Notification、通知页和 Navbar 未读 badge。
- 后台：Admin 首页、用户管理、漫画管理、小说管理、互动管理、活动日志。
- 创作者：漫画书架/Series/Part 上传页，小说书架/Novel 管理页/Chapter 编辑页。
- 布局：普通页面使用标准 Navbar/Footer；创作工作页桌面端使用自动隐藏 Navbar；漫画阅读页完全沉浸。
- 部署：Linux + systemd + Nginx + SQLite + uploads + 备份脚本。

## 文档维护规则

- 主目录文档只写当前代码事实、当前操作方式和明确的近期规划。
- 阶段性审计、临时统计、一次性 follow-up 不放主目录；必要时放 `docs-archive/`。
- 旧文档和代码冲突时，以代码为准。
- 新增 API、模型、页面、部署变量、布局模式后，同步更新对应文档。
- 不把设想写成已实现；规划内容必须明确标注为“方向”或“后续”。
- Git diff 中已经被移走的带日期临时文档删除记录可忽略，不视为当前文档缺失。

## 面向用户的产品功能

本节从开发维护角度概述当前前端承载的产品能力。描述重点是页面入口、角色权限、用户可见能力和模块边界，便于后续改动时判断影响面。

### 公共访问层

公共访问层面向未登录访客和普通登录用户，包含首页、项目页、作品入口页、关于页、公开用户页、漫画阅读链路和小说阅读链路。

首页承担站点入口和导航分发职责。项目页展示项目卡片。作品页是漫画和小说的统一入口。关于页承载静态站点说明或作者信息。

公开用户页展示用户公开资料，并挂载用户页留言能力。该页面属于公开内容页，但留言写入依赖登录态。

公共页面统一使用标准 Navbar/Footer 布局；漫画章节阅读页是例外，采用沉浸式阅读布局，不渲染全局 Navbar/Footer。

### 账号与当前用户

账号模块提供注册、登录、当前用户状态获取和前端登录态展示。注册受后端公开注册开关和人类验证约束，默认创建 reader 用户。

登录态影响导航栏、用户菜单、收藏按钮、评论输入区、通知入口、创作者入口和后台入口。角色能力主要按 reader、author、admin 区分。

当前用户资料页支持修改显示名、简介和头像。头像能力包括上传、列出历史头像、切换当前头像、清空当前头像和删除自己拥有的头像资源。

### 漫画公共阅读

漫画公共阅读链路包含漫画归档、漫画系列详情、漫画 Part 详情和漫画章节阅读。

漫画归档展示公开 Series。系列详情展示公开 Part 及其公开章节。Part 详情展示单个 Part 的封面、标题、简介、owner、更新时间、章节目录、收藏状态和评论区。

漫画章节阅读页按页展示图片资源，并提供返回目录、上一话、下一话等阅读导航。该页面同时挂载章节评论区。

收藏粒度为漫画 Part，不是 Series 或 Chapter。收藏按钮只对登录用户可操作，未登录时引导用户先登录。

### 小说公共阅读

小说公共阅读链路包含小说归档、小说详情和小说章节阅读。

小说归档展示当前可访问的 Novel。小说详情展示小说信息、章节列表、收藏状态和小说评论区。小说章节阅读页渲染 Markdown 正文，并支持正文中的章节图片。

收藏粒度为 Novel。小说详情页和小说章节页分别挂载评论区，评论目标不同。

当前小说模型没有 visibility/status 字段，公共小说接口默认返回所有小说和章节；这一点属于产品和权限边界的重要现状。

### 评论互动

评论系统是跨模块通用能力。当前前端挂载点包括用户页、小说详情、小说章节、漫画 Part 和漫画章节。

评论支持树状回复、回复目标展示、较长回复列表展开/收起、当前用户删除自己的评论、删除占位展示和图片附件。

评论图片支持选择、发布前预览、移除待上传项和发布后查看大图。评论写入和删除依赖登录态；评论读取对公开页面开放。

后台互动管理对同一套评论数据提供检索、上下文查看、图片预览、软删除和硬删除能力。

### 收藏与通知

收藏模块当前覆盖 Novel 和 Comic Part。前端在对应详情页展示收藏状态，并提供收藏/取消收藏操作。

通知模块面向登录用户，展示由评论、留言、收藏、章节发布和章节更新等事件派生的消息。通知列表支持搜索、类型/状态筛选、打开目标、标记已读、全部已读和删除。

通知生成依赖后端 OutboxEvent 处理流程。前端只消费已生成的 Notification，不负责事件派生。

### 创作者漫画工作流

创作者漫画区域面向 author/admin 中具备对应 Part owner 权限的用户。前端入口包括创作者首页、漫画书架、Series 管理页和 Part 工作区。

漫画书架展示当前创作者可管理的 Series。Series 管理页展示该 Series 下当前用户拥有的 Part，并提供创建 Part 和进入 Part 工作区的入口。

Part 工作区是漫画创作的核心页面，覆盖 Part 元信息维护、章节目录维护、章节上传发布和已有章节替换。能力包括重命名 Part、编辑 Part 简介、上传/更换 Part 封面、打开公开 Part 页面、重命名章节、移动章节顺序、删除章节、创建新章节和覆盖已有章节。

漫画上传区支持图片上传和 PDF 导入。PDF 导入主要用于新建章节；已有章节更新通过载入章节页面到待传区后覆盖发布。

该工作区在桌面端使用自动隐藏 Navbar 的工具型布局，主内容和上传抽屉分别承担目录管理与上传发布任务。

### 创作者小说工作流

创作者小说区域面向拥有 Novel owner 权限的 author/admin 用户。前端入口包括创作者首页、小说书架、Novel 管理页、新建章节编辑器和已有章节编辑器。

小说书架展示当前创作者拥有的 Novel，并提供创建 Novel 和进入管理页能力。Novel 管理页覆盖小说元信息、封面、章节目录、章节顺序和公开阅读入口。

小说章节编辑器支持 Markdown 编辑、预览、保存正文 buffer、发布章节、编辑已有章节和插入章节图片。章节图片上传后以 Markdown 图片链接形式进入正文。

正文 buffer 用于降低编辑中断风险；正式发布时再写入 NovelChapter。

### 管理员后台

管理员后台面向 admin 用户，包含后台首页、用户管理、漫画管理、小说管理、互动管理和活动日志。

用户管理覆盖用户列表和站点级注册开关等能力。漫画管理覆盖 Series、Part、Chapter、封面、简介、owner、排序、上传和删除。小说管理覆盖 Novel、Chapter、owner、正文、排序、封面和删除。

互动管理面向评论审核和数据清理，支持检索、上下文树查看、图片预览、软删除和硬删除。

活动日志用于审计关键操作，支持按 action、category、actor、target type、target、成功/失败状态和时间范围筛选。该页面对排查上传、编辑、删除、移动、owner 变更等问题有直接价值。

### 典型业务路径

漫画阅读路径：作品入口 -> 漫画归档 -> Series -> Part -> Chapter。登录用户可在 Part 层收藏，并在 Part 或 Chapter 层评论。

小说阅读路径：作品入口 -> 小说归档 -> Novel -> Chapter。登录用户可在 Novel 层收藏，并在 Novel 或 Chapter 层评论。

漫画发布路径：创作者漫画书架 -> Series -> Part 工作区 -> 上传图片或导入 PDF -> 发布新章节或覆盖已有章节 -> 检查公开 Part/Chapter。

小说发布路径：创作者小说书架 -> Novel 管理页 -> 新建或编辑 Chapter -> Markdown 编辑/预览 -> 保存 buffer 或发布 -> 检查公开 Novel/Chapter。

后台排查路径：活动日志定位操作 -> 进入对应管理模块核对数据 -> 必要时通过公开页面验证用户可见结果。

### 运行与部署相关的前端边界

前端通过 `VITE_API_BASE_URL` 决定 API base。开发环境通常指向 `http://127.0.0.1:18001`。

生产同源部署需要使用 `VITE_API_BASE_URL=""` 构建，使浏览器请求当前域名下的 `/api/...`。如果构建产物保留本地 API 地址，线上浏览器会访问用户设备上的 `127.0.0.1`，导致功能不可用。

生产 Web 服务器需要将 Vite `dist` 作为静态站点，并对 React Router 深层路径回退到 `index.html`。例如 `/works/comics/:seriesSlug/:partSlug` 由前端路由在 HTML 加载后匹配。

上传资源通过 `/uploads/...` 展示。生产环境需要保证 Web 服务器 `/uploads/` 映射和后端 `UPLOADS_DIR` 指向同一份文件树。
